# SEO Content Rules — Timmerfabriek Sint Nyk

## Principle
SEO supports the customer journey; it does not dictate unnatural copy. Each indexable page should have a clear reason to exist and satisfy a distinct search intent.

## Before writing any page
Confirm from the SEO research:
- target URL;
- primary search intent;
- primary keyword/theme;
- secondary topics;
- intended audience;
- relationship to parent/child/sibling pages.

If these are unclear, do not improvise a target. Flag the page.

## One page, one primary purpose
A page may rank for many related queries, but it should have one dominant purpose.

Do not create separate near-duplicate pages merely for singular/plural, synonyms, minor keyword variants or nearby towns.

## Search intent
The opening section should quickly confirm that the visitor is on the right page and answer the core intent. Avoid 150 words of generic company introduction before discussing the product/service.

## Headings
- Exactly one visible H1 per page unless the framework has a justified exception.
- H1 should accurately describe the page; primary keyword use should be natural.
- H2/H3 hierarchy should reflect actual subtopics, not keyword repetition.
- Do not make headings vague (`Onze kwaliteit`, `Waarom kiezen voor ons?`) when a specific heading would be more useful.

## Title tags
When editable:
- make every title unique;
- lead with the useful topic where natural;
- add brand/local modifier only when helpful;
- avoid stuffing multiple keyword variants;
- prioritize clarity and click relevance over rigid character formulas.

## Meta descriptions
- unique and page-specific;
- summarize what the visitor will find;
- include a sensible next step where appropriate;
- no unsupported superlatives;
- do not treat meta descriptions as a ranking-factor keyword field.

## Body copy
- Answer practical buying/specification questions.
- Demonstrate expertise through detail.
- Include relevant terminology naturally.
- Do not target keyword density.
- Avoid padding pages to arbitrary word counts.
- Avoid duplicate boilerplate across all product pages.
- Do not add an FAQ merely to make the page longer.

## Internal linking
Every important product/service page should be considered for links from:
- relevant parent category;
- relevant sibling/related products;
- projects/case studies;
- informational content where applicable;
- homepage where strategically appropriate.

Anchor text should describe the destination naturally. Do not repeatedly use exact-match anchors everywhere.

## Cannibalisation
Before targeting a keyword/theme:
1. search `SITE-STRUCTURE.md` and `KEYWORD-RESEARCH.md`;
2. inspect existing related pages;
3. decide which URL owns the primary intent;
4. use other pages for genuinely distinct sub-intents.

Flag conflicts rather than optimizing two pages for the same job.

## Local SEO
Use real geographic relevance, not city-name stuffing.

Good local signals include verified:
- workshop/business location;
- actual service area;
- project locations;
- local case studies;
- contact details;
- practical delivery/installation coverage.

Do not mass-produce `[product] + [town]` pages without substantial unique value and a genuine business reason.

## E-E-A-T / trust
Where appropriate, strengthen pages with verified evidence:
- real project examples;
- original photography;
- clear company details;
- named/real expertise when owner approves;
- certifications and guarantees only when verified;
- transparent process;
- realistic answers about lead time, installation and scope.

Never manufacture trust signals.

## Product/category relationship
Category pages should help users choose and navigate. Child pages should answer the specific product intent in greater depth. Do not repeat the same 500-word introduction across both.

## Projects
Project pages should contain genuinely useful unique information when available:
- project type;
- location (if publishable);
- customer situation/challenge;
- product supplied;
- important choices/specifications;
- execution/result;
- related product-page links.

Never invent project details from photographs.

## FAQ
Use FAQs when questions are genuinely relevant to the page. Prefer real customer questions. Answers should be direct and factual.

Do not promise FAQ rich results or add schema solely because FAQs exist.

## Conversion
Each commercial page should have an appropriate next step. The CTA should match visitor readiness: request a quote, discuss a project, ask a question, or provide drawings/dimensions.

## AI-content quality gate
Reject/rewrite copy that:
- could belong to any timber company;
- repeats the keyword mechanically;
- overuses adjectives;
- invents facts;
- uses fake urgency;
- says `quality` without explaining what that means;
- contains long generic introductions;
- repeats identical benefits across every page.

## Technical preservation
When editing source files:
- preserve components, IDs, classes, structured data and tracking unless a change is required and understood;
- do not change canonical URLs, redirects, indexation directives or routing casually;
- run the project's available validation/build checks after changes.
